* Split ruby-llm and ruby-nlp skills out of genai

Two skill/agent extractions from the genai (Cognitive Architect) skill,
following the same pattern as the earlier multi-db split:

- ruby-llm: the RubyLLM gem ecosystem (chat, tool calling, streaming,
  embeddings, structured output via ruby_llm-schema, Rails persistence
  via ruby_llm-rails, MCP client via ruby_llm-mcp), plus the circuit
  breaker and OpenTelemetry instrumentation patterns that wrap it.
  Code samples are training-knowledge, not live-verified this session,
  and the skill says so explicitly.

- ruby-nlp: a curated 17-gem classical NLP toolkit (tokenization,
  sentence segmentation, POS/dependency parsing, WordNet lookup,
  fuzzy/TF-IDF/BM25 similarity, topic modeling, transformer inference),
  narrowed down from a larger inventory table by excluding gems that
  aren't language processing (deploy, image, audio, RDF, Ruby-code AST,
  generic JSON/subprocess tooling). Three Context7 IDs are flagged
  suspect/unverified pending a live resolve-library-id check.

genai keeps RAG/retrieval architecture (clause-level chunking, RRF,
pgvector, dspy, MCP server) and now points to both new skills for the
concrete gem calls inside that architecture. The orchestrator registry
grew from 11 to 13 entries; also fixes a pre-existing broken-link bug
in scaffold-patterns.md (relative links pointed one directory too
shallow).
